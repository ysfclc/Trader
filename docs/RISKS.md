# Risk register

_Last reviewed: 2026-11-19 against main commit `4ffd465e7c89a35d3a5c3b6125f8097b246b3b37`._

| ID | Risk | Severity | Current control / evidence | Required mitigation / trigger |
|---|---|---|---|---|
| R-01 | No physical-device acceptance has been performed. Share intents, navigation, backup document-picker behavior, restore UX and process-death behavior may differ on real Android/OEM builds. | High | CI runs 255/256 pass; test suite is JVM/Robolectric. | Install on Redmi Note 12 Pro 5G. Verify first launch, create/edit/search/archive/restore, Android share capture, workflow interaction, export, fresh-install restore, wrong-passphrase failure and data survival after process death. |
| R-02 | Restore is destructive replacement, not merge; selecting the wrong backup can replace the current workspace. | High | UI displays warning and requires acknowledgement; restore validates before one Room transaction. Wrong-passphrase and tamper tests verify that failed authentication leaves existing data unchanged. | Before restore, export the current workspace separately. Consider a pre-restore automatic safety snapshot only as a separately specified increment. Keep the replace semantics visible. |
| R-03 | A forgotten backup passphrase makes the backup unrecoverable. | High | Passphrase is not stored or transmitted; minimum length is 12 characters. | Warn the user to store the passphrase independently. Do not add a password-recovery promise or hidden escrow. |
| R-04 | Backup compatibility is currently strict: snapshot schema is version 1 and expects Room schema version 3. A later database migration will make older backup files fail unless compatibility is explicitly added. | High | Versioned/authenticated header, schema validation and dedicated backup tests; see `TraderBackupManager.kt`. | Any Room schema change must add backup-format migration/compatibility tests and document the supported upgrade path before release. |
| R-05 | Backup contains the seven current Room record groups only; it is not a full Android app/device backup. Preferences, external files, app permissions and other OS state are not included. | Medium | PR #8 scope explicitly limits the snapshot to current Room workspace data. | Keep export scope explicit in UI/help. Extend only when file/attachment storage is actually implemented and has its own backup contract. |
| R-06 | Workflow UI can be mistaken for automation. Steps are currently progressed manually; the WorkManager dependency does not mean a durable executor exists. | High | Registry/UI distinguish unavailable capabilities; startup recovery moves interrupted RUNNING steps to NEEDS_REVIEW and idle RUNNING runs to PAUSED; no executor or external adapter is wired. | Keep claims/UI honest. Do not enable automatic start until durable WorkManager execution, idempotency, cancellation, adapter timeouts and postcondition tests exist. |
| R-07 | Capability contracts are declarative; no browser/app/network/AI/communication executor exists, and generic field validation does not enforce adapter-specific semantics or quotas. | High | All 16 descriptors now declare typed inputs/outputs, cost disclosure, limit mode, side effects and required postconditions; registry validates required fields/types/unknown keys. PR #12 CI run 279 and post-merge main CI run 286 passed the full test/lint/build/signature/package pipeline (44 tests each). | Keep adapter-backed operations NOT_IMPLEMENTED until their selected adapter declares numeric byte/time/rate/concurrency limits and enforces source policy, consent, payload binding and postconditions with adapter tests. |
| R-08 | Current intake is limited to manual case entry and Android shared text/URL. Document, screenshot and voice capture are not implemented. | Medium | Current intake code is explicit and preserves original text/URL. | Add one input modality at a time, retaining raw original bytes/source metadata and parser provenance. |
| R-09 | Duplicate cases and merged entities can fragment a future buyer/supplier/contact graph. | Medium | No deduplication or automatic merging is currently claimed. | Implement deterministic candidates plus human-reviewed merge, with reversible provenance and tests; T1.7. |
| R-10 | Search and Android share/document-picker flows have no direct UI/instrumentation acceptance tests. | Medium | Repository/domain tests cover adjacent persistence and data transformations. | Add tests for search-field matching and ACTION_SEND parsing; verify share chooser and document picker on device. |
| R-11 | Debug APK has a CI debug signing identity; release signing and update continuity are not configured. | High | CI verifies signature and package identity only. No release keystore is committed. | Configure a dedicated Trader release keystore through protected GitHub secrets and verify upgrade/install path before public distribution. |
| R-12 | No browser/app automation, live web discovery, embedded AI, buyer/supplier matching or external communication adapter exists. | High | Capability registry shows unsupported operations; roadmap and tasks remain open. | Deliver a single evidence-backed vertical slice per adapter, with access-policy checks, provenance, human approval and observable postconditions. |
| R-13 | The local Room database does not currently use a dedicated application-level database encryption layer. | Medium | No SQLCipher or other Room database-encryption dependency is configured; Android app sandbox/device encryption still applies. | Decide on an at-rest encryption requirement based on the data threat model before storing credentials or highly sensitive evidence; do not mistake encrypted exports for encrypted live database storage. |
| R-15 | Cancelling a workflow while a step is RUNNING can falsely imply that its external side effect stopped. | High | Cancellation now routes the active step and run to NEEDS_REVIEW, clears approval, and cancels remaining non-active steps; regression tests passed in PR #14 CI run 292. | Review the actual provider outcome before retrying; physical-device workflow acceptance remains open. |
| R-14 | No release-grade production signing or real device validation means current build evidence is development-grade only. | High | Main artifact is `0.1.0-debug`, CI debug signed. | Keep release claims blocked until release signing and device acceptance are separately demonstrated. |

## Operating rule

A risk is not closed because a related screen or safeguard exists. Close it only with the mitigation evidence and update this file and `docs/STATE.md` in the same increment.
